# CV

Single-source-of-truth CV pipeline. The YAML at `../new-site/_data/cv.yml`
drives **both** outputs:

- **Website `/cv/` page** (al-folio, auto-rendered by Jekyll)
- **LaTeX PDF** (`vita.pdf`, compiled from a generated `.tex` in the original
  libertine/HRule/etaremune style)

So one edit — in the YAML — updates both the live site and the downloadable PDF.

## Files

| File | Role |
|------|------|
| `../new-site/_data/cv.yml` | **Canonical source.** Edit this. |
| `build_tex.py` | Reads the YAML → writes `vita.tex` in the libertine/HRule/etaremune style. |
| `vita.tex` | **Generated — do not hand-edit.** Regenerated by `make tex` on every build. |
| `vita.pdf` | Compiled PDF. This is the file linked from the website's CV download button. |
| `vita.tex.legacy` | Archived original hand-written tex. Kept for historical reference only. |
| `Makefile` | Build targets (see below). |
| `requirements.txt` | Build dependency: `PyYAML`. |

## Workflow

1. **Edit `../new-site/_data/cv.yml`.** Add a new paper, new intern, a new talk — whatever.
2. **Regenerate & compile:**
    ```bash
    cd cv
    make          # runs `make tex` then `make pdf`
    ```
3. **The website updates automatically** (Jekyll picks up the YAML change on next build; the PDF download link points at `cv/vita.pdf`).

## Make targets

| Target | Action |
|--------|--------|
| `make` (default) | Full rebuild: YAML → `vita.tex` → `vita.pdf`. |
| `make tex` | Regenerate `vita.tex` only. |
| `make pdf` | Run `pdflatex` (twice) on `vita.tex`. Requires a TeX distribution installed. |
| `make diff` | `diff -u vita.tex.legacy vita.tex` — compare the generated `.tex` against the archived hand-written version. |
| `make install` | Create `.venv/` and install `PyYAML`. Run once. |
| `make clean` | Remove `vita.pdf` + `pdflatex` aux files. (Does not remove `vita.tex` — regenerate with `make tex`.) |

## Dependencies

- **Python ≥ 3.9** with `PyYAML`. Install via `make install` (creates a local venv).
- **pdflatex** (via MacTeX on macOS, or TeX Live on Linux). The generator uses the
  same packages as `vita.tex`: `geometry`, `hyperref`, `enumitem`, `etaremune`, `libertine`.
- Optional: **MacTeX** small variant (`BasicTeX` + `sudo tlmgr install etaremune libertine`) if you
  want a minimal TeX install.

## YAML schema (used subset)

`cv:` top-level object containing:

- `name`, `location`, `email`, `website`
- `social_networks:` list of `{network, username}`
- `sections:` ordered map; keys become section titles. Supported shapes:
  - `Education` → list of entries with `institution`, `area`, `degree`, `start_date`, `end_date`, `highlights`
  - `Experience` → list of entries with `company`, `position`, `location`, `start_date`, `end_date`, `highlights`
  - `Skills` → list of entries with `name` and `keywords: []`
  - Any other section → list of `{bullet: "..."}` items (rendered as itemize); publication subsections (`Refereed Conference Publications`, `Refereed Journal Publications`, `Refereed Workshop Publications`, `Surveys`, `Tutorials`, `Book Chapters`) render as numbered `etaremune` lists.
  - Sections named `Service — X` or `Mentorship — X` auto-group under a shared section with sub-subsections.

## LaTeX rendering details

`build_tex.py` translates inline markdown in YAML strings:

- `**bold**` → `\textbf{bold}`
- `*italic*` → `\emph{italic}`
- `[text](url)` → `\href{url}{text}`
- Escapes raw specials (`& % $ # _ ~ ^ \`) in literal text.

Section ordering in the output mirrors the original `vita.tex`:
**Education → Positions → Awards & Distinctions → Publications (with subsections) →
Academic Experience (Invited Talks, Service, Mentorship, Funding, Teaching) → Technical Skills → References**.

## Caveats

- **Never hand-edit** `vita.tex` — your changes will be overwritten on the next
  `make tex`. Always edit the YAML.
- If a YAML section doesn't map to any of the recognized types above, it falls
  through to a generic bullet list (assumes `{bullet: "..."}` entries).
- `vita.tex.legacy` is only kept for reference. It is not part of any build step
  and can be deleted once you're confident you'll never need to compare against
  the pre-generator version.
